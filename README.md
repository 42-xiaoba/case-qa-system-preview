# 智能案例问答系统（案例智答）

> 把案例原文、团队分析报告和 20 余篇学术文献一并"读进肚子"的 AI 问答助手——有问必答、句句标出处、数据不打诳语。
>
> 本项目为**清华大学智能社会治理公共政策案例分析大赛**而建，服务于备赛与答辩场景。

---

## 一、这是什么？（项目定位）

备赛时手头的资料又多又杂：案例原文、《案例分析报告一稿》、选题报告、20 多篇基层治理领域的学术文献……想找一个数据、核对一处观点，往往要在几十个 PDF 里来回翻。

这个系统做的事情很简单：**让 AI 提前"读完并记住"所有资料，然后像一位随叫随到、随身带着全部资料的队友一样回答你的问题。**

它对你有三个承诺：

| 承诺 | 具体表现 |
|------|----------|
| **答案有出处** | 每个论断都标注来源：（一稿·章节名）、（作者，年份）、《文献名》、（案例文本·部分名），可直接回查原文 |
| **不知道就承认** | 资料里没有的内容，它会明确说"现有资料未涉及"，绝不现场编造 |
| **关键数据零篡改** | 报表压减 50%、覆盖 11 个街道 72 个社区等核心数字被写进"铁律"，原样引用不许改动 |

> 小科普：系统采用 **RAG（检索增强生成）** 技术——AI 回答前会先在本地知识库里"查资料"，把最相关的段落找出来再作答，而不是凭记忆自由发挥。这就像开卷考试：允许翻书，但只能抄书上有的。

## 二、功能一览

### 🤖 智能问答（核心功能）

在底部输入框输入问题即可。回答支持**逐字流式输出**（打字机效果），并自动按"一稿 > 案例原文 > 文献汇编"的可信度优先级组织内容。

可以这样问：

```
这个案例的研究意义是什么？
交易成本理论如何应用到"报表通"案例中？
就业帮扶链取得了什么成效？
一稿的分析框架是怎么搭建的？
范炜烽那篇文献对"数字悬浮"的解释是什么？
```

### 🔗 追问卡片（延伸提问）

每次回答完成后，下方会自动出现两张可点击的小卡片：

- **🔗 相关延伸**：顺着本次回答继续深挖的好问题
- **🌱 新话题**：同一主题下换个角度的新问题

点击卡片，问题自动填入输入框，回车即问——不知道下一问什么的"选择困难症"直接治愈。

### 🖼️ 图片识别问答

案例里的图表、流程图、政策截图看不懂？点左侧栏「🖼️ 添加图片」上传（PNG/JPG/WebP/GIF，一次一张），再用一句话描述你想问什么，视觉模型会结合图片内容和案例知识一起回答。未配置视觉密钥时此功能自动隐藏，不影响其他功能。

### 📄 PDF 对照阅读

右侧栏完整展示《案例报告》PDF，与左侧对话独立滚动、互不干扰：

| 操作 | 效果 |
|------|------|
| 鼠标滚轮 | 上下翻页 |
| ➕ / ➖ 按钮 | 放大 / 缩小（0.5x ~ 3.0x） |
| Shift + 滚轮 | 横向滚动放大后的页面 |

一边问"报表压减率是多少"，一边在右栏翻到对应页核对，答辩前自检特别好用。

### 💬 多轮对话记忆

连续追问时，AI 记得前面聊过什么（最近 6 轮原样保留；聊得再长，更早的内容会被自动压缩成摘要带上，不会"聊着聊着就失忆"）。左侧栏「🗑️ 清空对话」可一键重新开始。

### 🛟 多模型自动切换（稳定性的秘密）

系统同时接入多家大模型服务，按以下顺序排队值守：

```
文本回答：商汤 SenseNova 6.8 FlashLite（主力）
          ↓ 忙线/超时自动切换
          智谱 GLM-4.7-Flash（双 Key 轮换）
          ↓
          智谱 GLM-4.6v-Flash → OpenRouter Nemotron → GLM-4.6v（末位兜底）

图片识别：智谱 GLM-4.6v-Flash（主力）→ SenseNova → GLM-4.6v
```

主力模型高峰期卡顿时，系统会在几秒内自动换下一位上场——**你什么都不用做，也不会察觉切换发生过**。

## 三、三分钟上手

### 第 1 步：安装环境

需要 Python 3.10 或更高版本（[python.org](https://www.python.org/downloads/) 下载，安装时勾选 "Add Python to PATH"）。然后在项目文件夹打开终端执行：

```bash
pip install -r requirements.txt
```

### 第 2 步：配置密钥

在项目根目录创建 `.env` 文件（就是新建文本文档后改名为 `.env`），按需填入以下密钥：

| 变量名 | 必填？ | 用途 | 去哪申请 |
|--------|--------|------|----------|
| `GLM_API_KEY` | ✅ 必填 | 备用文本模型 + 兜底保障 | [智谱开放平台](https://open.bigmodel.cn) 注册后在"API Keys"页创建 |
| `SENSENOVA_API_KEY` | 强烈推荐 | **主力回答模型**，额度充足、响应快 | [商汤日日新](https://platform.sensenova.cn) 控制台创建 |
| `GLM_V_API_KEY` | 可选 | 图片识别功能 | 智谱开放平台（与上面同一个 Key 也可） |
| `OPENROUTER_API_KEY` | 可选 | 额外一道保险 | [openrouter.ai](https://openrouter.ai) |

填写格式（一行一个）：

```ini
GLM_API_KEY=你的智谱密钥
SENSENOVA_API_KEY=你的商汤密钥
GLM_V_API_KEY=你的视觉密钥
```

> 🔒 `.env` 已被 `.gitignore` 排除，**不会被上传到 GitHub**，放心填写。只有 `GLM_API_KEY` 是硬性必需——哪怕只配这一把钥匙，全链路也能跑通。

### 第 3 步：启动

本地使用推荐开两个终端：

```bash
# 终端 1：启动后端服务（提供检索、记忆等能力）
python app.py

# 终端 2：启动前端界面
streamlit run ui.py
```

浏览器访问 **http://localhost:8501** 即可开始提问。（后端固定走 8000 端口，无需额外配置。）

<details>
<summary><b>直连模式</b>（不想开后端？）</summary>

只执行 `streamlit run ui.py` 也可以用——前端检测不到后端时会自动改为直接调用模型 API，问答功能完整可用（适合云端部署场景）。

## 四、常见问题 FAQ

**Q：回答大概多久？**
正常情况首字约 8 秒内出现，整段回答约 15 秒完成，同时附带追问卡片。若某家服务商临时拥堵，自动切换会有几秒额外等待，属正常现象。

**Q：想换成我们自己的案例？**
三步：① 替换 `case.txt`（案例原文）、`case_report.pdf`（展示用 PDF）和《清华案例分析报告一稿.docx》；② 更新 `resources/文献资料要点汇编.md` 与 `resources/` 下的文献；③ 重跑知识库构建脚本：

```bash
pip install pdfplumber        # 构建脚本的专用依赖，运行主程序不需要
python scripts/build_knowledge.py
```

脚本会自动切块、自检并输出 `kb/chunks.json`。

**Q：想让 AI 的说话风格 / 引用规则变一变？**
编辑 `config.yaml` 即可，提示词分三层（人设 → 业务规则 → 输出格式），改完重启生效，全程不用碰代码。

**Q：`scripts/` 里那些文件是干嘛的？**
团队内部的质量工具：`eval.py` 用于评测检索质量（配套 `golden_qa.json` 标准问答集），其余 `test_*.py` 是各模块的自测脚本。日常使用完全不需要理会。

**Q：怎么部署到网上让队友远程访问？**
推送到 GitHub 后，登录 [Streamlit Cloud](https://streamlit.io/cloud) → New app → Main file path 填 `ui.py` → 在 Secrets 页面按上面的变量名添加密钥 → Deploy。`.env` 不上传没关系，Secrets 就是它的云端替身。

## 五、项目结构

```
├── app.py                # FastAPI 后端：检索、记忆、流式接口、PDF 服务
├── ui.py                 # Streamlit 前端主入口（界面与交互都在这）
├── config.yaml           # ⭐ 全局配置：提示词三层 / 模型参数 / 降级链 / 检索预算
├── core/
│   ├── router.py         # 问题路由：判断该走文本回答还是图片识别
│   ├── knowledge_base.py # 本地知识库：关键词检索 + 加权重排
│   ├── pipeline.py       # 组装回答的输入：资料 + 历史 + 提示词
│   ├── memory.py         # 对话记忆：近期保留 + 超长滚动摘要
│   ├── llm_client.py     # 多模型调用封装 + 自动降级切换
│   ├── prompt_manager.py # 三层提示词组装 + 视觉消息构建
│   └── config.py         # 配置加载（读取 config.yaml + .env）
├── kb/                   # ⭐ 已建好的知识库（克隆即用，无需重建）
│   ├── chunks.json       # 全部资料切成的知识块
│   └── tier0_card.md     # 常备知识卡（每问必带的核心事实）
├── resources/            # 参考文献 PDF + 文献要点汇编
├── scripts/              # 知识库构建 / 质量评测工具（日常不用管）
├── case.txt              # 案例原文
├── case_report.pdf       # 右栏展示的案例报告 PDF
├── requirements.txt      # 依赖清单
└── .env                  # 你的密钥（自行创建，不上传 Git）
```

标 ⭐ 的两个文件是日常最常打交道的：调行为改 `config.yaml`，换材料重建 `kb/`。

## 六、技术架构速览（给有兴趣的同学）

```
用户提问
   │
   ▼
┌─────────┐   文本    ┌──────────────────────────────────────┐
│ 路由分类 │──────────▶│ 组装输入：常备知识卡 + BM25 检索Top6  │
└─────────┘           │ + 最近对话(或其摘要) + 三层提示词      │
   │ 图片             └──────────────┬───────────────────────┘
   ▼                                 ▼
视觉模型 GLM-4.6v-flash        SenseNova 主力（GLM 系列热备接力）
                                 │ 流式输出
                                 ▼
                   回答正文 ＋ 后台并行预生成的追问卡片
```

- **检索**：jieba 分词 + BM25 关键词检索，章节命中加分、自有文档加权（一稿可信度 > 外部文献），低分块丢弃以控制回答速度；
- **记忆**：超过阈值自动把早期对话压缩成摘要，长对话不爆上下文；
- **可靠性**：全局并发闸门防限流雪崩、多 Key 轮换分摊配额、七级端点自动降级。
